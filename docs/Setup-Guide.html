Part 0

Six words, so the rest makes sense

Repository (repo)
A folder of files with a full memory of every change ever made to it. The Distill repo is the folder on this Mac, and GitHub holds a copy.
GitHub
The website that stores the copy. It is the backup, the history, and the thing Vercel watches.
Commit
A saved snapshot with a one-line note, like "Change the headline". Claude makes these.
Push
Sending new commits from this Mac up to GitHub. Until a push happens, GitHub does not have the changes.
Vercel
The host. It watches the GitHub repo and, every time a push lands, puts the new version of the site on the internet within about a minute.
Supabase
The database. The signup form writes each email into a table there. You read the list in its dashboard.
The flow you will set up: Claude edits files on this Mac, commits, pushes to GitHub, Vercel publishes. You never have to touch code. You do have to create the accounts, because they need your email and your password, and Claude never types those.
Part 1

GitHub: secure the account, hide the repo, let this Mac push

Do all of this in the browser where you are signed in as distillAI-maker.

  1. Confirm the email address on the account

    GitHub sends a verification email when an account is created. Until it is clicked, some settings are locked.

    Gmail (disttilai@gmail.com) → open the email from GitHub → Verify email addressYou should see: a green banner on GitHub, or nothing at all if it was already verified. To check: click your profile photo (top right) → Settings → Emails. The address should say Verified.
  2. Turn on two-factor authentication

    GitHub asks most accounts to do this within a few weeks anyway. Doing it now avoids a surprise lockout later. Use the GitHub Mobile app or Google Authenticator on your phone.

    Profile photo → Settings → Password and authentication → Two-factor authentication → Enable two-factor authentication → Authenticator app → scan the code with your phone → enter the 6 digits → Download recovery codesSave the recovery codes in the same place as the company passwords. They are the only way back in if the phone is lost.
  3. Make the repository private

    Right now anyone can read it. The docs folder holds the copy, the research and the routing table, which are yours. Private costs nothing and Vercel deploys private repos fine.

    github.com/distillAI-maker/distillV1 → Settings (tab at the top of the repo) → scroll to the bottom, Danger Zone → Change visibility → Change to private → confirm the name → I have read and understand these effects → Make this repository privateYou should see: a small "Private" label next to the repo name.
  4. Invite your personal account as a collaborator

    This Mac is signed in to GitHub as ivannadil. GitHub refused the push because that account has no access to the repo. Giving it access fixes the push for good, and it is the normal way teams work: the company account owns, people contribute.

    Repo → Settings → left sidebar, under Access: Collaborators → Add people → type ivannadil → click the match → Add ivannadil to this repositoryYou should see: ivannadil listed as "Pending invite".
  5. Accept the invite from the ivannadil account

    The invitation goes to the email address on the ivannadil account. Two GitHub accounts cannot be signed in to the same browser at once, so use a private window or a different browser for this step.

    Open a private window → github.com → sign in as ivannadil → go to github.com/distillAI-maker/distillV1/invitations → Accept invitationYou should see: the repo page, with "Private" next to its name, viewed as ivannadil.
  6. Tell Claude to push

    The three waiting commits go up in a few seconds.

    The invite is accepted. Push the code to GitHub.
  7. Check that the files arrivedRefresh github.com/distillAI-maker/distillV1You should see: folders docs, public, supabase, plus README.md and vercel.json. Below the file list the README text is displayed. Near the top right of the file list, "commits" shows a number of 4 or more. Click it to see the history: each line is one saved snapshot with its note.
How to read the repo page from now on. The file list is the current state. "Commits" is the history. The green Code button is only for downloading; you will not need it. Never click the pencil icon to edit files on the website while Claude is editing on the Mac, or the two copies drift apart. If you ever do, tell Claude "pull the latest from GitHub" before asking for more changes.
Part 2

Vercel: put the site on a public address

Free plan, no card. One rule matters: Vercel only lets the owner of a repo import it, so Vercel must be connected to the distillAI-maker account, not to ivannadil.

  1. Make sure the browser is signed in to GitHub as distillAI-makergithub.com → profile photo top right → the name under it should read distillAI-makerIf it says ivannadil, sign out first. Vercel copies whichever GitHub account the browser is using.
  2. Create the Vercel account with GitHubvercel.com → Sign Up → choose Hobby (the free plan) → enter a name → Continue with GitHub → Authorize VercelYou should see: the Vercel dashboard, mostly empty, with an "Add New" button.
  3. Give Vercel access to the repoAdd New → Project → under Import Git Repository, if distillV1 is not listed: Adjust GitHub App Permissions (or Install) → pick distillAI-maker → Only select repositories → distillV1 → InstallYou should see: distillV1 in the list with an Import button.
  4. Import and deploy

    The project name becomes the web address, so keep it short and lowercase. Everything else can stay as it is: the repo has a vercel.json that already tells Vercel to serve the public folder with no build.

    Import next to distillV1 → Project Name: distill (or distillv1) → Framework Preset shows "Other" → leave Build and Output Settings alone → DeployYou should see: a build log for about 30 seconds, then a confetti screen with a preview of the page. Click Continue to Dashboard.
  5. Open the public addressProject dashboard → Domains, or the link under the preview image → it looks like distill.vercel.app; if that name was taken, Vercel adds a few letters, like distill-abc1.vercel.appYou should see: the Distill page, live, for anyone with the link. The form will say "Signup is not connected yet" until Part 3 is done. That is expected.
  6. Optional: pick a nicer vercel.app nameProject → Settings → Domains → Edit next to the vercel.app entry → type a new name → Save
About "free" on Vercel. The Hobby plan is free with no time limit, and its terms say it is for personal, non-commercial use. A pre-launch page collecting emails is the normal case people run on it. When Distill starts charging customers, plan to either move to Vercel Pro ($20 a month) or to a host whose free plan allows commercial use, such as Cloudflare Pages. The site is one folder, so the move is an afternoon.
Part 3

Supabase: make the form save emails

Free plan. The form needs two values from Supabase, and the database needs one script run once.

  1. Create the Supabase account and projectsupabase.com → Start your project → Continue with GitHub (as distillAI-maker) → New organization: name Distill, plan Free → New project: Name distill, Database Password: click Generate and save it in the company password list, Region: the one closest to your users (for the US, West US or East US) → Create new projectYou should see: a project page that says "Setting up project" for one to two minutes, then a dashboard with a left sidebar. The database password is not needed for the site, but it is needed if you ever have to recover the project.
  2. Create the signups table

    The script lives in the repo at supabase/schema.sql. Open it on GitHub, copy all of it, and run it once.

    github.com/distillAI-maker/distillV1 → supabase → schema.sql → the "copy raw file" icon (two overlapping squares) → back to Supabase → left sidebar: SQL Editor → New query → paste → Run (bottom right, or Cmd+Enter)You should see: "Success. No rows returned". Then left sidebar → Table Editor → a table called signups with 0 rows.
  3. Copy the two connection valuesLeft sidebar: Settings (gear at the bottom) → API Keys → copy Project URL (looks like https://abcdefgh.supabase.co) and the Publishable key (starts with sb_publishable_)If the page shows tabs, use the "API Keys" tab, not "Legacy". The publishable key is safe to share and safe to put in the page: the script from step 2 only lets it add a row, never read one. Do not copy anything called Secret or service_role.
  4. Give the values to Claude

    Claude puts them into the top of the page file, commits and pushes. Vercel publishes the new version within a minute.

    Connect the form. Project URL is https://…supabase.co and the publishable key is sb_publishable_…
  5. Test with your own emailOpen the vercel.app address → click Get My Free Stack Audit → enter your email and a wearable → submitYou should see: "Thanks. You're on the founding list". Then in Supabase → Table Editor → signups → Refresh: one row with your email, lower-cased, and the time.
  6. Try the same email againYou should see: the same thank-you. Repeats are treated as success on purpose, and the table still has one row.
The one Supabase catch. Free projects are paused after about a week with no activity, and while paused the form fails. A signup counts as activity, and so does opening the dashboard. If you open Supabase and see a "Paused" badge, click Restore; it takes a couple of minutes and keeps every row. Once real traffic starts, the Pro plan ($25 a month) never pauses.

Part 6

If something breaks

Claude says the push was denied (403)Steps 4 and 5 of Part 1 are not both done. Check Settings → Collaborators on the repo: ivannadil must be listed without "Pending".
Vercel cannot find distillV1Either the browser was signed in to GitHub as ivannadil when Vercel was created (only the owner can import), or the Vercel GitHub app was installed with "Only select repositories" and distillV1 was not ticked. Fix: Vercel → Settings → Git → GitHub → Configure, tick distillV1.
The site shows a Vercel 404 pageVercel served the wrong folder. Project → Settings → Build and Deployment → Framework Preset must be Other and Output Directory must be public. Save, then Deployments → Redeploy.
The form says "Signup is not connected yet"The two Supabase values are not in the page yet, or the push after adding them has not happened. Part 3, steps 3 and 4.
The form says "Could not save that email"Usually the script in Part 3 step 2 was not run, or was run with an error. Run it again; it is safe to repeat. Also check the Supabase project is not paused.
The form says "Could not reach the server"The Project URL was pasted with a typo, or the Supabase project is paused. Open supabase.com and look for a Paused badge.
I edited a file on GitHub's website and now Claude's changes conflictTell Claude "pull the latest from GitHub and keep both changes". It will sort it out.
